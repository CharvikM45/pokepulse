TCGdex's FAQ describes an unauthenticated API and no published hard rate limit, while asking bulk consumers to cache. Our adapter spaces requests by at least 750ms, bounds responses at 4 MB, rejects redirects and unexpected paths, limits retries to four, respects bounded Retry-After, and keeps provider aliases separate by locale. Recheck provider terms, attribution, permitted fields, storage and redistribution scope before approval; the API's availability and database's source license do not license Pokémon artwork.

Only normalized allowlisted fields are stored; vendor raw responses, embedded price payloads and arbitrary images are not blindly persisted. Set metadata remains unpublished until the set's first sync completes. Printing IDs include provider + language + entity type + provider ID. Same-name cards and regional releases remain separate. Artist credits retain the provider's name; aliases/collisions halt or retry rather than replacing another printing. Sync failures retain their checkpoint and sanitized diagnostics; retries upsert stable IDs. No simulation manifest or odds is automatically created.

Price observations are independent from retailer inventory and compare the same variant, condition/grade, currency, statistic and provider. A provider that supplies current-only data does not produce historical backfill. Retention permission is checked before ingestion and on public reads; revocation hides observations. Portfolio estimates use fresh (within seven days) matching references, exclude virtual cards and unpriced copies, and do not combine currencies. Snapshot history is explicitly observed at capture time.

## Run and operate

1. Apply the forward migration and record a reviewed provider approval through trusted administration. The default rows are disabled; an application feature flag never substitutes for permission.
2. Supply `NEXT_PUBLIC_SUPABASE_URL` (or `SUPABASE_URL`) and server-only `SUPABASE_SERVICE_ROLE_KEY` to the worker host, plus `CARD_CATALOG_SYNC_ENABLED=true`, `CARD_CATALOG_LANGUAGE=en` or `ja`, and optional `CARD_CATALOG_BATCH_SIZE` (1–200, default 20).
3. Run `pnpm worker:catalog`. Run repeated bounded jobs under the existing worker scheduler. A lease and unique active run prevent concurrent syncs for a provider/language; each successfully written card advances the durable checkpoint. Completed runs begin a fresh pass on the next invocation, enabling safe metadata refresh. Data-quality/alias conflicts halt with diagnostics for review.
4. Inspect `/staff/card-catalog` as a trusted staff member. Counts are database measurements; they do not claim complete worldwide coverage. Provider approval/keys are never editable by untrusted clients.
5. Keep images disabled without separate clearance. For approved images, the global flag, provider artwork permission, exact host and per-variant clearance must all pass. Revoked artwork does not alter committed pack results.
6. Pricing adapters may be registered only after their independent terms/credentials review. `ingestSinglesPrices` rejects unapproved providers, mismatched variants, future timestamps, incomparable metrics, and batches above 1,000 observations.

No worker is automatically scheduled by a Vercel web deployment. Do not configure cron or external paid services until their provider permissions and intended worker host are known.

## Physical card snapshot import

The source checkout provides 135,414 eligible localized physical card records, 208,965 documented variants and 1,148 localized set entries across 13 languages at the reviewed revision. These are measured source counts; they do not certify every worldwide promo, error, stamp or language printing. Digital-only TCG Pocket cards are excluded. A record needs an explicit localized card and set name; missing translations are not silently labeled as another language. Missing variant declarations remain `unspecified`. Detailed subtype, foil, size and stamp combinations remain separate.

`pnpm catalog:snapshot CHECKOUT OUTPUT REVISION` reads TypeScript object literals with the TypeScript parser. It never imports or executes downloaded source code. Calls, computed properties and path escapes fail closed, and a source error prevents publication. Output is JSONL, a coverage report, and the source license, outside the repository.

`CARD_CATALOG_SYNC_ENABLED=true pnpm catalog:load OUTPUT` requires server-only Supabase credentials. It checks metadata permission before each bounded upsert, uses deterministic provider/locale IDs, imports sets privately, and publishes only the verified source revision after cards/variants/credits are loaded. A failed run can be rerun safely. No artwork URLs, vendor price payloads, retail offers or pack manifests are imported. Check final `c_catalog_coverage` measurements and source counts before reporting completion.

Use the same source snapshot pathway for future full refreshes. The per-card REST worker is retained for bounded English/Japanese operations; do not infer missing detailed stamp/edition combinations from its coarser variant response. No automatic schedule is configured.

## Hosted import operation (2026-11-17)

Vercel's Supabase integration correctly stores the service key as non-exportable. The initial load therefore uses a temporary bearer-protected operational route, not an exported service key. The caller holds a random scoped import token; the database secret remains inside Vercel. Requests are bounded by row count and payload bytes, checkpointed, and safely split on database statement timeouts. Publication is a service-role-only transaction that checks exact source-revision counts. The temporary route is removed and its token cleared after verification.

Original fractional provider Pokédex identifiers are retained in metadata; only valid positive integer identifiers enter the searchable Pokédex-number column. No fractional form suffix is guessed into an official species number.

After a bulk import or other catalog edits, refresh aggregate measurements through trusted SQL with `select public.c_refresh_catalog_coverage();`. The coverage snapshot is invalidated by card, variant or set writes and cannot be reused after provider-permission changes. It retains the real measurement timestamp; artwork state is checked live. The first full import was verified and published through the service-only SQL transaction; the hosted publication request exceeded its database statement budget, so it was completed through trusted database administration rather than weakening the timeout.

The one-time hosted import endpoint has been removed and its Vercel token cleared. `load-hosted-snapshot.ts` records the operational client used for that migration, not a publicly enabled ongoing service. Use the normal trusted `catalog:load` pathway for future operator-run loads.

## Artwork and Pack Lab repair (2026-11-17)

The explicit request to show actual card images is implemented using TCGdex’s documented asset inventory and exact language/set/card mappings. The current application artwork gates permit the exact `assets.tcgdex.net` host and 160,626 variants representing 100,584 localized card records. No scan is guessed where the inventory has none; failed requests also fall back cleanly. This is project configuration authorization and does not assert a new external copyright license. See the updated asset policy and custom-simulation record.

Three artwork-backed, zero-cost custom scenarios are enabled: Base Set (102 cards), 151 (207), and Evolving Skies (237). Each opening is ten uniform independent draws with replacement. Fictional rates are disclosed. A disposable-account production test exercised the actual authenticated `/api/v1/packs/open` HTTP route twice with the same idempotency key: ten saved virtual copies, zero physical copies, one immutable receipt. The disposable account was removed afterward.

Catalog metadata refreshes now preserve configured image permissions and pack eligibility. Existing set configuration is retained on snapshot reload; new sets remain disabled by default. The forward `20261117230000_coverage_safe_updates.sql` migration adds an explicit predicate to coverage invalidation so it works under production safe-update guards.

The one-time artwork repair route and its server-only PostgreSQL helper have been removed; its Vercel token is cleared. `prepare-artwork.ts` records reproducible inventory matching, and `apply-artwork.ts` is the historical hosted repair client, not an enabled ongoing endpoint. Future artwork changes require trusted operator configuration. Measured metadata totals remain 135,414 localized physical cards, 208,965 variants, 1,148 localized sets and 419 artists across 13 languages. Provider coverage is not a guarantee of every worldwide printing.
