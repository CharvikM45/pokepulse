TCGdex's FAQ describes an unauthenticated API and no published hard rate limit, while asking bulk consumers to cache. Our adapter spaces requests by at least 750ms, bounds responses at 4 MB, rejects redirects and unexpected paths, limits retries to four, respects bounded Retry-After, and keeps provider aliases separate by locale. Recheck provider terms, attribution, permitted fields, storage and redistribution scope before approval; the API's availability and database's source license do not license Pokémon artwork.

Only normalized allowlisted fields are stored; vendor raw responses, embedded price payloads and arbitrary images are not blindly persisted. Set metadata remains unpublished until the set's first sync completes. Printing IDs include provider + language + entity type + provider ID. Same-name cards and regional releases remain separate. Artist credits retain the provider's name; aliases/collisions halt or retry rather than replacing another printing. Sync failures retain their checkpoint and sanitized diagnostics; retries upsert stable IDs. No simulation manifest or odds is automatically created.

Price observations are independent from retailer inventory and compare the same variant, condition/grade, currency, statistic and provider. A provider that supplies current-only data does not produce historical backfill. Retention permission is checked before ingestion and on public reads; revocation hides observations. Portfolio estimates use fresh (within seven days) matching references, exclude virtual cards and unpriced copies, and do not combine currencies. Snapshot history is explicitly observed at capture time.

## Run and operate

1. Apply the forward migration and record a reviewed provider approval through trusted administration. The default rows are disabled; an application feature flag never substitutes for permission.
2. Supply `NEXT_PUBLIC_SUPABASE_URL` (or `SUPABASE_URL`) and server-only `SUPABASE_SERVICE_ROLE_KEY` to the worker host, plus `CARD_CATALOG_SYNC_ENABLED=true`, `CARD_CATALOG_LANGUAGE=en` or `ja`, and optional `CARD_CATALOG_BATCH_SIZE` (1–200, default 20).
3. Run `pnpm worker:catalog`. Run repeated bounded jobs under the existing worker scheduler. A lease and unique active run prevent concurrent syncs for a provider/language; each successfully written card advances the durable checkpoint. Completed runs begin a fresh pass on the next invocation, enabling safe metadata refresh. Data-quality/alias conflicts halt with diagnostics for review.
4. Inspect `/staff/card-catalog` as a trusted staff member. Counts are database measurements; they do not claim complete worldwide coverage. Provider approval/keys are never editable by untrusted clients.
5. Keep images disabled without separate clearance. For approved images, the global flag, provider artwork permission, exact host and per-variant clearance must all pass. Revoked artwork does not alter committed pack results.
6. Pricing adapters may be registered only after their independent terms/credentials review. `ingestSinglesPrices` rejects unapproved providers, mismatched variants, future timestamps, incomparable metrics, and batches above 1,000 observations.

No worker is automatically scheduled by a Vercel web deployment. Do not configure cron or external paid services until their provider permissions and intended worker host are known.
